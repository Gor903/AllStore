# Мутационное тестирование

Покрытие говорит, какие строки тесты **исполнили**. Мутации говорят, какие строки тесты
**проверяют**. Это разные числа, и расходятся они там, где это важнее всего: строка с
условием может быть покрыта на сто процентов и не проверена ни разу.

mutmut портит код по одной правке за раз — `>` на `>=`, `and` на `or`, `return x` на
`return None` — и прогоняет набор. Тест покраснел: мутант убит, строка проверяется. Набор
остался зелёным: **мутант выжил**, и эту строку можно сломать, не уронив ни одного теста.

## Как запускать

```bash
make mutate-module M=app.core.totp   # один модуль или пакет — так и смотрят
make mutate-report                   # кто выжил
make mutate                          # всё целиком: часы, не минуты
```

Прогон идёт только по unit-тестам: интеграционным нужна настоящая postgres, а мутант
запускает набор заново для каждой правки. Мутируется то, что unit-тесты покрывают, —
зеркально `scripts/tests-tree-exempt.txt` (список в `[tool.mutmut]` в `backend/pyproject.toml`).
Мутант в маршруте или репозитории выжил бы не потому, что тест плох, а потому, что его
проверяют интеграционные тесты, которых здесь не запускают: шум, в котором тонет сигнал.

`mutants/` — рабочий каталог mutmut, он в `.gitignore`.

Порядок тестов внутри прогона зафиксирован (`-p no:randomly`): мутанту нужен быстрый ответ
«красный или зелёный», а не свой сид на каждом из тысяч запусков. Гринлет-слой SQLAlchemy под
мутациями не просыпается — unit-тесты до базы не доходят, и поэтому же прогон укладывается в
секунды на мутанта.

## В CI этого нет, и не по забывчивости

Прогон по всему бэкенду — это тысячи запусков набора. В CI он стоил бы часы на каждый PR и
красную галочку за мутанта, который никого не беспокоит. Поэтому порога нет и галочки нет:
мутациями смотрят на пакет **перед тем, как его менять**, и после того, как написали тесты, —
чтобы узнать, проверяют ли они хоть что-нибудь.

## Что это уже нашло

### `app/core/client_ip.py` — две настоящие дыры

```
app.core.client_ip.x__vouched_for__mutmut_3: survived
-        return False
+        return True
```

`_vouched_for` для адреса, который вообще не адрес, начал отвечать «доверяю». С этой правкой
любой вызывающий, чей peer не парсится как IP, становится доверенным прокси — а значит
`X-Forwarded-For` от него читается как правда. Это обход всех лимитов: вписал в заголовок
любой адрес, и талля считается на него. Ни один тест этого не заметил.

```
app.core.client_ip.x_client_ip__mutmut_33: survived
-    return hops[-1]
+    return hops[+1]
```

Ветка «вся цепочка наша» брала дальний конец. Тест на неё был — с цепочкой из двух хопов, где
`-1` и `+1` это один и тот же элемент. Цепочка из трёх убивает мутанта.

Оба закрыты тестами в `backend/tests/unit/app/core/test_client_ip.py`.

### `app/schemas/session.py` — список устройств без устройств

```
app.schemas.session.xǁSessionReadǁof__mutmut_2: survived
-        user_agent=row.user_agent,
+        user_agent=None,
```

Все проверки на `user_agent` были про пустой случай: «браузер не представился — это всё ещё
устройство». Про непустой не было ни одной, поэтому `SessionRead`, теряющий браузер целиком,
проходил набор. Экран, на который человека отправляют со словами «посмотрите, откуда входили»,
показал бы список пустых строк.

## Измеренная база

Снято на текущем наборе; это точка отсчёта, а не цель.

| пакет | мутантов | убито | выжило | без тестов |
| --- | --- | --- | --- | --- |
| `app/schemas/*` | 430 | 346 | 41 | 43 |
| `app/core/client_ip.py` | 47 | 45 | 2 | 0 |

Числа сняты командой `make mutate-report` после прогонов по этим двум целям; оба выживших в
`client_ip` — эквивалентные (см. ниже), поэтому дальше там чинить нечего.

«Без тестов» — код, которого unit-тесты не касаются вовсе: например `ContactsResponse.of`,
собирающий ответ там, где тест работает с `ContactWrite` напрямую. Это не выживший мутант, это
отсутствующий тест, и читать эти две колонки надо вместе.

## Как читать выжившего

Не каждый выживший — дыра. Три вида, и различать их приходится глазами:

1. **Настоящий пробел.** Строка делает решение, которое никто не проверяет. Пишется тест.
2. **Эквивалентный мутант.** Правка ничего не меняет: `strict=False` → `strict=None` (оба
   ложны), имя заголовка в другом регистре (Starlette читает их без учёта регистра). Убить
   такого нельзя, и гнаться за стопроцентным счётом поэтому бессмысленно.
3. **Проверять нечего.** Мутация в строке, у которой нет наблюдаемого следствия, — скажем,
   в тексте лога. Тест на такое был бы тестом на формулировку.

Считать процент убитых как KPI — способ получить тесты, написанные ради счёта. Польза
мутаций в конкретном списке выживших: каждый из них — вопрос «а что сломается, если это
поменять?», и ответ на него либо тест, либо пожатие плечами с чистой совестью.
