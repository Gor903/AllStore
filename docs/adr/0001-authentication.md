# 0001. Авторизация: JWT access + refresh с ротацией, оба в httpOnly cookie

Статус: superseded by [ADR 18](0018-server-side-sessions.md)
Дата: 2026-09-19

## Контекст

AC 2.2 требует, чтобы выход инвалидировал сессию, а раздел 11.3 продуктового плана — чтобы
блокировка аккаунта отбирала доступ. Публичные страницы рендерятся на сервере (раздел 20),
то есть Next.js должен получать данные пользователя при SSR. Магазины живут на субдоменах
`*.allstore.am` (раздел 8), значит авторизация должна работать между субдоменами.

## Решение

Access-токен — JWT (HS256, подпись на `SECRET_KEY`), время жизни 15 минут.
Refresh-токен — непрозрачная случайная строка, в БД хранится только её хэш, время жизни 30 дней.

Оба уходят в cookie: `HttpOnly`, `Secure` (кроме локальной разработки), `SameSite=Lax`,
`Domain=.allstore.am` — чтобы витрина на субдомене и API на основном домене видели один вход.

Refresh ротируется: каждое обновление отзывает старый токен и выдаёт новый. Повторное
использование уже отозванного токена отзывает всю цепочку — это признак кражи.

Выход удаляет запись refresh-токена и очищает cookie. Access живёт максимум 15 минут,
поэтому чёрный список access-токенов не заводим; там, где нужен мгновенный запрет
(блокировка аккаунта), сервис проверяет статус пользователя в БД.

Для изменяющих запросов — CSRF-токен по схеме double submit, так как авторизация в cookie.

## Альтернативы

- **Сессии в БД.** Мгновенная инвалидация без ротации, но запрос в БД на каждый вызов API
  и лишний шаг при будущем мобильном приложении (раздел 17).
- **JWT в заголовке Authorization.** Токен пришлось бы хранить в localStorage — это XSS
  и неудобство при SSR: серверный рендер не видит localStorage.

## Последствия

- Нужна таблица refresh-токенов (владелец, хэш, срок, отзыв, замена) и её миграция.
- Мгновенный запрет доступа работает только через проверку статуса пользователя — это
  обязательная часть `get_current_user`, а не опция.
- До 15 минут после блокировки access-токен формально валиден — отсюда проверка статуса.
- Cookie на `.allstore.am` означает, что локальная разработка идёт на `*.allstore.localhost`.
