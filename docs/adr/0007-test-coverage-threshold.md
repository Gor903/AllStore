# 0007. Порог покрытия: 80% на изменённые строки

Статус: accepted
Дата: 2026-09-19

## Контекст

Раздел 9 плана сборки требует тесты на новую логику как часть Definition of Done. Нужен
порог, который это подкрепляет, но не превращается в гонку за процентом.

## Решение

Блокирует merge только покрытие строк, изменённых в PR: не ниже 80%. Считается `diff-cover`
по отчёту coverage относительно `origin/main`.

Общее покрытие по backend печатается в логе CI и merge не блокирует.

## Альтернативы

- **Общий порог (например, `--cov-fail-under=70`).** Проще настроить, но большой хорошо
  покрытый модуль маскирует новый непокрытый код, а после рефакторинга порог падает
  по причинам, не связанным с PR.
- **Без блокирующего порога.** Возвращает вопрос к ревью, а он про это забывает первым.

## Последствия

- В CI нужен полный клон (`fetch-depth: 0`), иначе сравнение с `origin/main` невозможно.
- Отчёт coverage должен быть в формате XML — это дополнительный флаг для pytest.
- PR, состоящий только из миграции или конфигурации, изменённых исполняемых строк почти
  не содержит — порог на нём не срабатывает, и это правильно.
- Порог на frontend не вводится: пока там один компонент и Vitest только появился.
  Отдельное решение — когда появится заметная клиентская логика.
