# Architecture Decision Records

Один файл на решение: `NNNN-краткое-название.md`, нумерация сквозная.
Структура записи: Контекст → Решение → Альтернативы → Последствия → Статус
(`proposed` / `accepted` / `superseded by NNNN`). Принятые записи не переписываются:
изменение решения — это новый ADR со ссылкой на предыдущий.

Решения, которые раздел 11 плана сборки требует зафиксировать до начала соответствующего этапа:

| # | Решение | Нужно к этапу |
| - | ------- | ------------- |
| 1 | JWT или session-based авторизация | 2 |
| 2 | Формат хранения паролей и политика сложности | 2 |
| 3 | Стратегия кэширования публичных страниц | 6 |
| 4 | Генерация TypeScript-типов из OpenAPI (инструмент и место в CI) | 2 |
| 5 | Провайдер email-уведомлений | 8 |
| 6 | Стратегия резервного копирования PostgreSQL | 1–9 (до продакшена) |
| 7 | Минимальный порог покрытия тестами и где он блокирует CI | 2 |
