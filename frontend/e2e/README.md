# e2e

Playwright-сценарии всего стека: браузер ходит через nginx в тот же backend и frontend,
что и человек. Vitest рядом проверяет компоненты поодиночке — здесь проверяется, что они
собраны вместе правильно.

## Что проверяется

`seller-to-catalog.spec.ts` — путь, ради которого площадка существует: продавец
регистрируется, открывает витрину, оставляет способ связи, заводит товар; модератор
допускает продавца и одобряет товар; покупатель находит товар в каталоге и попадает на
витрину магазина по её собственному адресу.

## Как запустить

```bash
npx playwright install chromium   # один раз
make e2e                          # из корня: поднимет стек, заведёт модератора, прогонит сценарий
```

`make e2e` спрашивает адрес у самого стека, поэтому свой `HTTP_PORT` в `.env` менять не
нужно. Если стек уже поднят, достаточно:

```bash
cd frontend && E2E_BASE_URL=http://localhost:8080 npx playwright test
```

## Модератор

В роль `moderator` нельзя зарегистрироваться — её выдаёт скрипт:

```bash
docker compose exec backend python -m scripts.grant_role e2e-moderator@e2e.allstore.am e2e-password-1 moderator
```

Повторный запуск ничего не ломает. Адрес и пароль переопределяются переменными
`E2E_MODERATOR_EMAIL` и `E2E_MODERATOR_PASSWORD`.

## Про данные

Сценарий ничего за собой не убирает: каждый прогон заводит нового продавца, новый
субдомен и новый товар с уникальным именем. На стенде от этого копятся строки — это
осознанно, чистить базу под тестом означало бы проверять не тот стек, которым
пользуются.

Адрес по умолчанию — `http://localhost:8080`, тот же хост, что в `NEXT_PUBLIC_API_URL`
стека. Браузер на другом хосте упёрся бы в CORS и в SameSite-cookie, а не в проверяемое
поведение; витрины на субдоменах открываются по ссылкам, которые рисует само приложение.
