# Модули без зеркального unit-теста, и почему.
#
# Список только сокращается: скрипт падает, если у модуля из него тест уже появился, если
# модуля больше нет, и если строк стало больше бюджета ниже. Дописать строку можно, но тогда
# придётся поднять бюджет — и это будет видно в диффе отдельной правкой, а не спрячется
# среди кода.
#
# Что здесь осталось — это не «руки не дошли». Это модули, у которых поведения без базы нет:
# unit-тест на них был бы набором моков, проверяющим, что код вызывает те функции, которые
# он вызывает. Такой тест не ловит ошибок и мешает менять код. Их поведение проверяют 973
# интеграционных теста на настоящей postgres, и объединённое покрытие бэкенда это видит.
#
# Граница проведена так: если модуль можно спросить без базы — у него есть зеркальный тест
# (схемы, модели, конверт ошибок, лимитер, подписанное состояние, ключи устройств, ассистент,
# фабрика приложения, движок, воркер). Если нельзя — он здесь, под своим заголовком.
#
# budget: 60
